## Architecture boundaries

The product serves developers/teams with bounded review, requirements-only, solution-only and full requirements-to-solution modes. Inputs may be ideas without a repository, one pinned main GitHub repository, permitted public evidence and explicitly selected local text/source/diff snapshots. Code is read only, never run or changed. Requirements must be explicitly confirmed at an exact immutable version before solution generation; saving or model output is not confirmation. A new requirements head invalidates current confirmation atomically; solution start/send/commit recheck the bound head and confirmation. Explicit save and AI commit create versions; keystrokes do not. Original private raw Draft stays separate. Accept the goal and scope, pin versions, investigate key documents and expose findings, conflicts, unread material and verification steps. Without an authoritative baseline, review produces observations and hypotheses rather than invented compliance requirements. Drafting may propose requirements/AC, but only the human can accept them. Local material uses bounded explicit upload, not a filesystem bridge; known private ancestry survives edits/imports, while unknown external provenance remains unverified. Important conflicts end the Turn with progress; a reply starts a linked Turn under the same Case caps. GitHub direct adapters lead; DeepSeek Search/Fetch supplement only when needed and complete query/URL disclosure is permitted. Browser remains zero with implementation deferred; MCP stays research scope.

The target is independent API, Worker/LangGraph stages and a new independent PostgreSQL cluster in WSL, with Windows accessing the UI. Application tables own conditions, tasks, work/call identities, permissions, evidence, reports and costs. Checkpoints hold bounded committed references, never authority. Use [ADR5](docs/design/adr/0005-windows-worker-wsl-postgres.md) for deployment/recovery, [ADR7](docs/design/adr/0007-interactive-evidence-decision-sessions.md) for sessions and [ADR8](docs/design/adr/0008-m1-engineering-baseline.md) for decisions. Keep Vue on the API, state serializable and `browser-use/` upstream-owned.

Every outbound call needs current admission and exact request binding. Unknown outcomes stop new project outbound; completed/unknown calls are not resent by replanning, recovery or a new ID. Supervisor continuity and current Pg controls both constrain authority. Lost continuity isolates restored identities and disables research/memory; new CLI credentials only qualify limited draft/history access. No independent freshness proof means no restored paid-research authority.

Current M1 disables every Memory feature entry: manual/automatic, API/CLI, default profile/framework preload, old checkpoint refs, import/restore/rebuild and background paths. No Memory candidates, reads, writes, retrieval or model injection; active Memory refs stay empty and match actual requests. Trace records disabled/not_applicable and null hits/writes with feature_disabled, not tested zeroes. Case evidence, accepted conditions, documents and audit remain persistent. Explicitly selected historical reports use normal SourceSet permissions and private ancestry without resolving Memory refs. DEC-AC-17/DEC-M1-04 remain deferred and unverified; current Context belongs to 03a and Token qualification to 03b. Real reuse need, independent review and separate scope approval are required to reopen Memory; reserved capacity cannot be reassigned.

Keep personal draft/authorship separate from team/project sharing. Reading, retention, model processing, sharing and public-supplier disclosure have separate scopes. Private ancestry survives derived reports and public citations. App installation/repository authority is distinct from local membership and Task execution grants. Each bounded response/page/SSE frame checks the current read session and source permissions; one already claimed bounded delivery may remain in flight. Logout stops new reads without cancelling an independently authorized Task. Detailed parameters belong to CURRENT_CONTRACTS.

The sole protocol is draft-m1-2; the M1 capability reference is draft-m1-capabilities-2. Its public material index is pending independent preparation; this batch creates no formal prompts/gold.
