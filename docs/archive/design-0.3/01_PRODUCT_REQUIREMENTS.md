# Adaptive Research Agent 最终产品需求（PRD）

状态：**APPROVED（设计）**｜版本：Gate 1 冻结版 0.3｜日期：2026-10-18｜实施：未授权

本文件是已批准、尚未实施的目标产品设计；G2-00 权威迁移前，**不替代**现行 [V1 Spec](../specs/V1_SPEC.md)、[V1 Contracts](../contracts/V1_CONTRACTS.md)及历史 [D7 No-Go](../audits/V1_DELIVERY_REPORT.md)。`VERIFIED` 指当前源码或运行记录支持；`INFERRED` 指有依据但缺调用级证据；文中 `PROPOSED` 指尚未实现的目标或尚未执行的验收。需求 ID 与验收 ID 的双向关联见 [09 追踪矩阵](09_TRACEABILITY_MATRIX.md)。

## 1. 产品决策与使用者

**PROPOSED 定位：面向开发者的自主技术选型调研与证据验证 Agent。** 目标用户是需要在有限时间内比较技术方案的开发者和小团队工程负责人。其痛点是跨官方仓库、文档和发行说明核实信息耗时，普通摘要容易漏字段、错归属或丢失出处。核心价值是把具体研究目标变成可观察的执行过程、可核验的事实和有来源的报告；无法完成时给出真实原因与已验证的部分结果。

| 候选业务 | 用户价值与可验收结果 | 现有复用与工程展示 | 主要代价/风险 | 决策 |
| --- | --- | --- | --- | --- |
| 开源项目发现与技术选型 | 为候选项目核实名称、官方仓库、许可证、安装命令；对应固定 B01 | GitHub API、浏览器、主体归属、去重、报告全部可复用 | 搜索命中与事实归属不稳定 | **主场景**：最能展示多源检索和证据链 |
| 技术文档研究与方案对比 | 对比官方文档中的路由、异步支持和安装方式；对应 B02 | 浏览器观察、语义评估与通用报告可复用 | 文档格式差异和长上下文成本 | **同一产品的第二场景**：验证工具选择与语义抽取 |
| GitHub Release / Changelog 调研 | 核实版本、日期和两项变更；对应 B03 | GitHub 结构化结果、浏览器发布页与版本归属规则可复用 | “最新”随时间变化，标题与正文易混 | **同一产品的第三场景**：验证动态资料与主体归属 |

三类场景使用同一任务、证据、报告与验收流程，**不**建立三套专用产品。B01–B03 的固定原文和字段以 [Benchmark Protocol](../benchmark/BENCHMARK_PROTOCOL.md#fixed-cases-and-expected-fields)为准；网页上的当前版本等动态值在每次原始记录中保存并核源。招聘展示价值来自真实成功率、失败复盘与可解释取舍，不来自功能数量。

**当前基线（VERIFIED）**：`frontend/src/App.vue` 已提供目标输入、最近任务、状态、时间线、取消和报告；`backend/api/research.py` 暴露六条路由；`backend/services/research.py` 连接 TaskManager、AgentLoop 和持久化。r12 的 18 次真实尝试三组完整完成率均为 0，三次独立 UI 业务验收均失败；详见 [D7 记录](../audits/V1_DELIVERY_REPORT.md)。因此“有页面和 API”不能表述为“研究业务可交付”。

## 2. 用户旅程、故事与业务闭环

1. 用户输入具体、可验证的研究目标；API 校验并返回任务 ID 和 `queued`，历史列表显示该任务。
2. 取得并发槽后，Agent 初始化子目标，逐轮观察、规划、调用 GitHub 或浏览器工具、评估证据并持久化事件；详情页通过 SSE 与历史补读展示真实步骤。
3. 用户查看事实卡片中的内容、主体、来源 URL、证据片段、对应步骤和验证状态；未通过验证的候选内容不得作为已核实事实展示。
4. 达到证据和目标条件时展示带来源报告；预算、信息不足或工具故障时展示 `partial`/`failed`、停止原因与未完成项。用户可取消；重启后可读取已持久化终态和轨迹，但不会断点续跑。

| 故事 | 验收意图 |
| --- | --- |
| US-01 开发者提交 B01 类型任务 | 快速获得可比较的候选项目与逐项官方来源；缺字段时不能假装完成。 |
| US-02 开发者研究 B02 官方文档 | 路由、异步和安装结论可回到确切官方页面核对。 |
| US-03 开发者研究 B03 版本 | 版本、发布日期、变更归属于同一发布记录，且注明资料抓取时点。 |
| US-04 开发者观察或中止长任务 | 看见真实阶段、步骤、成本和失败原因，取消后不再产生成功终态。 |
| US-05 开发者重看旧任务 | 刷新或重启后取回持久化轨迹、终态和已有报告，无虚构续跑。 |

## 3. 功能需求与验收

优先级：P0 为四周业务闭环必需；P1 仅在 P0 放行条件未受影响时交付。下表的验收都是 **PROPOSED**；目前的单元或 Mock 通过不证明真实任务通过。详情数据仍使用现有六路 API；后续若发现 DTO 不足，必须在 [04 数据/API 契约](04_DATA_AND_API_CONTRACTS.md)标记最小兼容变更。

| ID / 优先级 | 功能要求与边界 | 可检验验收 ID |
| --- | --- | --- |
| **FR-001 / P0** | 创建、排队、列表和详情：校验 1–4000 字目标，持久化 `queued` 后返回任务 ID；进程内并发上限默认 2，显示真实队列和六种状态。 | **AC-001**：有效请求返回 202 和可查询的 `queued`；空白/超长请求为 422，缺 Provider 配置为 503 且不落任务；并发任务不超过配置上限。 |
| **FR-002 / P0** | 每轮根据当前状态与观察动态选一个有效动作，路由到 GitHub/浏览器，区分技术失败与语义失败，评估后再推进子目标；重复 URL/查询和无进展受限。 | **AC-002**：Fake Provider/Tool 测试证明状态或观察变化能改变计划，非法动作不执行，技术失败有界重试，语义失败重新观察规划；B01–B03 真实执行轨迹含规划、工具与评估。 |
| **FR-003 / P0** | 从工具结果采集带来源事实，核对观察内容、主体身份、来源 URL 与目标字段；按步骤保存拒绝数量和原因码，不保存被拒绝候选正文；去重，事实 ID 贯穿报告。网页内容作为不可信数据。 | **AC-003**：未观察、错归属、重复、无来源事实不会进入已验证事实或报告；混合准入/拒绝步骤仍能读到拒绝数量和原因码；有效事实可由详情追到原步骤、证据片段和官方 URL；B01–B03 的逐项人工核源记录可复现。 |
| **FR-004 / P0** | 基于已接纳事实形成通用 `ResearchReport`，结论映射事实 ID 和来源；`partial` 明示未完成项，`failed` 不编造报告。 | **AC-004**：每项实质结论有已保存事实与官方来源；刷新/重启读取同一报告；B01–B03 每题三次真实尝试中至少两次按固定字段规则完整成功，九次原件全保留。 |
| **FR-005 / P0** | 显示任务历史和逐步时间线；持久事件为事实来源，SSE 队列只作唤醒；断线通过 `Last-Event-ID` 补读并在终态关闭。 | **AC-005**：详情与 `/traces` 反映同一已提交事件；断线重连不漏、不重复展示事件；慢订阅者不阻塞任务，断开后释放订阅。 |
| **FR-006 / P0** | 支持排队/运行取消、技术异常、预算/无进展终止及重启终结；终态不可变，`task_finished` 只落一次；有事实时合理 `partial`，无事实时 `failed`。 | **AC-006**：取消/完成竞态与重复取消给出一致结果；各终止路径持久化唯一终态事件并释放任务/浏览器资源；重启未完成任务以 `server_restart` 终结，不声称恢复。 |
| **FR-007 / P0** | 诊断视图展示已报告 Token、分阶段用量、耗时、失败类别、重复操作和停止原因；有未报告用量的调用时，总用量标“已知下界／实际未知”，不能显示为完整总额；**新增诊断元数据**不得携带密钥、Prompt 或页面正文。现有 `step_evaluated.tool_result.content` 会保存有界页面内容，故本机演示仅处理公开技术资料。 | **AC-007**：已报告调用可汇总且只计一次；Planner/Evaluator/独立修复/Reporter 的调用数、已报告用量与阶段耗时可追溯；未知用量调用单独计数、完整总额显示未知而非 0；新增诊断字段经脱敏并可在刷新后读取，不声称旧 trace 无页面原文。 |
| **FR-008 / P1** | 可选固定任务模板与已有报告的 Markdown 导出，不改变研究评分、Planner 及六路 API；模板仅帮助填写目标。 | **AC-008**：若进入批准范围，模板能编辑后提交且不改变固定 B01–B03 原文；导出与持久化报告 `markdown` 一致，不含未验证结论或敏感字段。P0 验收不依赖此项。 |

## 4. 非功能需求、限制与放行指标

| ID / 优先级 | 目标约束 | 可检验验收 ID |
| --- | --- | --- |
| **NFR-001 / P0 可靠性** | 沿用默认 30 步、900 秒、40,000 **已报告** prompt+completion Token、连续 5 次无进展上限；临时技术错误至多一次请求重试及独立的一次结构化修复。终态、取消、清理和 SQLite 事务一致；未知用量的预算不可验证性按 NFR-002 披露。 | **AC-N01**：上限测试、取消/并发竞态、异常和重启测试均证明有界终止、唯一终态和资源释放；真实失败不显示成功。 |
  | **NFR-002 / P0 性能与成本** | 默认最多 2 个并发研究任务；记录每次尝试的已报告 Token、可得的未知用量调用数、调用次数、重复 URL、墙钟耗时与失败原因。无请求级记录的 Provider 不推算阶段调用数。先修复业务完成率，再优化成本。 | **AC-N02**：B01–B03 九次与 G01–G03 三次均逐次记录；可观测且有上界的模型调用遵守 40,000 Token 预算；未知用量或上界无法保证时显式标为预算不可验证，不声称实际费用硬上限；平均与 P95 仅描述样本，不据失败早停宣称效率提升。 |
  | **NFR-003 / P0 安全** | 仅可信本机单用户、公开技术资料演示；密钥只在环境变量，已配置秘密在日志/事件/报告中脱敏；现有 trace 会保存有界工具页面内容，不能承诺自动清除任意敏感数据。显式导航目标须在发请求前通过 HTTP(S) 与公有地址校验，导航后的最终 URL 也校验；网页文本不能覆盖系统指令。DNS 校验到 Chromium 请求之间可能重绑定；重定向、点击、弹窗、子资源是否事前拦截未证实，不能宣称完整 SSRF 防护。 | **AC-N03**：直接私有/回环目标在导航前拒绝；受控 DNS 变化和重定向/点击等测试记录请求是否已发出，未证实事前拦截只能记为本机残余风险；恶意页索取测试密钥、诱导私网访问、伪造事实三个 canary 不得出现越权请求、泄漏或无来源结论；已配置密钥扫描通过；任务输入/浏览范围限公开资料，禁止公开部署。 |
| **NFR-004 / P0 可观测性** | 以 `task_id`、`event_id` 关联结构化日志、持久轨迹、阶段耗时、错误类别和真实重现记录。 | **AC-N04**：任一失败尝试能从任务 ID 追到事件顺序、停止原因、用量及原始评测记录；无敏感原文。 |
| **NFR-005 / P0 可维护性** | 保持 Vue→FastAPI→Service/TaskManager→AgentLoop→工具的方向；领域状态不存 BrowserSession/数据库 Session；Python/前端锁定工具链与回归测试。 | **AC-N05**：受影响 Python 单元/集成、Ruff、类型或配置检查及前端 type-check/test/build 的实际命令结果存证；破坏 API/状态契约的变更不得放行。 |
| **NFR-006 / P0 本机部署** | 可重复本机启动、初始化 SQLite、配置 DeepSeek 和可选 GitHub 凭据、启动 Chromium；停机释放任务和浏览器。 | **AC-N06**：按 README 在干净本机环境启动、提交和读取任务；错误配置启动检查可解释，停机重启后未完成任务终结且历史可读。 |

**业务最低放行（PROPOSED）**：B01–B03 各三次真实模型、真实工具、官方来源的独立尝试，逐题至少 2/3 完整成功；九次原件与失败记录全部保留，固定字段覆盖至少 **68/75**。另将 G01–G03 各一次预先冻结的独立泛化任务分表报告，至少 2/3 完整成功；全部十二次保留。所有实质结论须可追溯且人工核源准确，目标 100%。此小样本只是验收门槛，不支持统计显著性主张。真实模型测试另需费用授权，当前 r12 结果仍为 **No-Go**。详细评分、测试分层和 Go/No-Go 规则分别见 [05 测试与评测](05_TEST_AND_EVALUATION.md)、[06 验收与发布](06_ACCEPTANCE_AND_RELEASE.md)。

## 5. UI、状态与异常路径

下表是目标交互，现有 `App.vue` 的页面块可继续演进；**没有**新的事实/报告 CRUD API。所有成功态必须来自已提交的任务与事件，而非前端模拟。

| 视图 / 用户目标 | 数据来源与主要字段 | Loading / Empty / Error / Partial / Success、操作与前端验收 |
| --- | --- | --- |
| 创建 / 提交明确目标 | `POST /api/research`：`goal`、`id`、`status` | 提交中禁重；空白/超长即时提示，422/503 显示 API 原因；202 后选择真实任务。 |
| 列表 / 找回任务 | `GET /api/research`：ID、目标、状态、时间 | 加载、空列表、请求错误、六态标签；点击进入详情，刷新后仍可找回。 |
| 执行详情 / 判断是否继续 | `GET /api/research/{id}`：状态、完成度、停止原因、报告 | 加载、404、运行、`partial`、`completed`、`failed`、`cancelled` 区分；运行中可取消，终态操作禁用。 |
| 时间线 / 理解动作 | `/events` 与 `/traces`：`event_id`、时间、步数、事件、失败摘要 | 空轨迹、断线提示及补读；每个事件只展示一次，不把“工具调用成功”当成事实已验证。 |
| 事实证据 / 核对结论 | 已持久化 `step_evaluated` 载荷与报告支持事实 ID；拟议步骤级拒绝摘要见 04 | 无事实时说明原因；准入事实卡可打开经校验的官方 URL、查看证据与状态；拒绝数量和原因码只在步骤诊断中展示，不把拒绝候选当成已验证事实。 |
| 报告 / 使用结论 | 任务详情中的 `ResearchReport`：findings、来源、Markdown、未完成项 | 运行中占位；`partial` 明示缺口；`failed` 无报告时解释；成功结论可点开来源。 |
| 诊断 / 复现失败 | 任务详情、持久 trace 与拟议阶段用量事件：Token、耗时、错误类型、停止原因 | 缺失显示“未知”；失败分类与原始轨迹可对应；不展示密钥或页面敏感原文。 |

各视图的五态与操作验收如下；`N/A` 表示该状态对该视图无业务意义，不能用占位成功替代真实结果。

| 视图 | Loading / Empty | Error / Partial / Success | 操作与前端验收 |
| --- | --- | --- | --- |
| 创建 | 提交中禁重复；空目标提示格式 | 422/503 明确原因；partial N/A；202 仅显示 queued，不显示成功研究 | 输入、提交、修正目标；测试重复点击和无 key |
| 列表 | 骨架/空列表说明 | 请求失败可重试；partial/completed 等六种真实标签 | 选择任务、刷新；测试恢复后排序与状态 |
| 执行详情 | 读取中/尚无步骤 | 404 与服务错误；partial 显示已知事实及缺口；completed 才显示完整 | 刷新、取消；测试终态后操作禁用 |
| 时间线 | 连接中/尚无持久事件 | 断线补读提示；partial 与 success 均呈真实终态事件 | 查看步骤与来源；测试 event_id 去重、重连、断开清理 |
| 证据卡 | 加载 trace/尚无准入事实 | 缺片段显示“未保存原文”；partial 保留已有事实；success 显示事实 ID、步骤、官方来源 | 打开经安全 URL 校验的来源；测试错归属不出现在已验证卡 |
| 报告 | 生成中/无报告 | 报告不可用显示原因；partial 标未完成；completed 显示带引用报告 | 查看来源、可选导出；测试事实 ID 与 Finding 映射 |
| 诊断 | 读取事件/无用量写“未知” | 读取失败可重试；partial/failed 显示停止原因；completed 仍保留成本记录 | 按阶段查看 Token/耗时；测试旧记录无字段及脱敏 |

正常路径是创建→排队→运行→已验证事实→报告→`completed`。异常路径分别是输入/配置错误、工具临时失败后有界重试、语义失败后重新观察、无证据 `failed`、有证据 `partial`、主动取消 `cancelled`、重启时 `server_restart`；边界包括相同来源重复、计划指向失效元素、数量目标已满但另一子目标未完成、取消与终态竞态、SSE 断线和静默订阅者。状态定义以源码与 [V1 Contracts](../contracts/V1_CONTRACTS.md)为当前依据，目标细则见 [03 数据流与状态](03_DATA_FLOW_AND_STATE.md)。
