# Gate 2 验收、Go/No-Go 与本机交付

> 状态：**APPROVED（设计）**；实施未授权。这是未来开发的放行契约，不改变 [V1 冻结规范](../specs/V1_SPEC.md)或[D7 历史 No-Go](../audits/V1_DELIVERY_REPORT.md)。设计冻结不等于业务验收通过。

## 1. 当前结论与验收责任

**VERIFIED**：2026-10-17 D7 报告中，r12 三组各六次真实 benchmark 的完整完成率均为 0%；三次独立真实 UI 任务 B01–B03 亦均失败，未形成合格引用报告。其测试与核源证据不能被受控 Fake 测试代替。当前业务状态为 **No-Go**。后续任务以独立 `run_id` 与任务 ID 验收；需求负责人核对业务字段、QA 核对测试/原始记录、安全审查核对密钥与 URL 边界，最终由用户批准业务完成。

## 2. 三层最低放行条件

| 层级 | 最低条件（全部满足） | 证据 |
| --- | --- | --- |
| 工程 | 已批准 P0 需求按 ID 实现；Python 3.12/3.13 锁定环境离线 pytest、Ruff check/format、配置与编译检查通过；前端 type-check/test/build 通过；受影响 API/状态契约无意外破坏；无密钥泄漏和 P0 阻断；故障修复有失败先行回归 | 对应 commit/工作树指纹、实际 CI run、测试输出、审查记录；未运行项写明原因，不能以本地历史结果替代当前结果 |
| 业务 | 固定 B01–B03 各三次真实模型及工具端到端尝试，每题至少 2/3 完整成功；另有 G01–G03 各一次预先冻结的独立泛化尝试，至少 2/3 完整成功；真实 Vue、API、AgentLoop、SQLite 与 SSE 路径；全部十二次包括失败保留 | 十二个独立任务 ID、脱敏原始记录、事件/数据库对账、UI 截图、人工核源表、失败原因；两组结果分开报告 |
| Agent 质量 | B01–B03 九次总体字段覆盖率至少 68/75（≥90%）；所有实质结论的来源追溯率与来源准确率均 100%；终态与报告一致，失败无伪造成功；取消/异常/重启测试无双终态和资源泄漏 | 按 [测试评测基线](05_TEST_AND_EVALUATION.md)重算的字段键与人工核源表、原始链接、资源关闭与竞态测试 |

**完整成功**：任务终态为 `completed`、`completion_level=full`，报告显式给出该案例所有 Expected Fields，且每项有可打开的相应官方来源，无人工核查发现的事实矛盾；任务终态、页面和数据库一致。`partial` 即使字段齐全也须先解释未满足的子目标，不计完整成功；`completed` 但缺字段或核源失败同样不计成功。此句是对既有“完整任务成功”的可测化，不放宽字段或状态门槛。来源追溯率分母为报告中所有实质结论，分子为可映射到 `ResearchFact` 与源 URL 的结论；来源准确率分母为所有已追溯结论，分子为官方页面实际支持的结论。若分母为零，指标记 **N/A 且业务不通过**，不得报 100%。B01–B03 字段覆盖率分母固定为 `3×(10+10+5)=75`，失败与部分运行仍进入分母；每个字段须有明确值及官方来源并经人工核验才得分。G01–G03 用独立的 10/10/5 字段表和原始记录，**不并入** 75 的分母，也不改旧 benchmark 评分。逐结论核源字段、冲突处理与版本时间窗口见 [05](05_TEST_AND_EVALUATION.md#3-新版评测协议建议与历史-r12-分离)。

## 3. 指标与目标

| 指标 | 最低放行 | 后续优化目标与判读 |
| --- | --- | --- |
| 完整任务成功率 | B01/B02/B03 各 ≥2/3；G01–G03 合计 ≥2/3，分组报告 | 扩大任务集与重复次数后再设稳定性目标；十二次样本不作显著性结论 |
| 字段覆盖率 | B01–B03 九次汇总 ≥68/75，三类案例分别报告；G01–G03 各自报告 | 目标 100%；不能通过改变旧评分或省略失败来提高 |
| 来源追溯/准确 | 两者均 100%，每条实质结论人工核源 | 扩大不同官方站点和时间窗口；无证据结论一条即阻断 |
| 任务耗时 | 每次遵守 900 秒硬上限；记录均值及 P95 | 先建立成功任务的耗时基线，再提出缩短目标；失败早停不是性能提升 |
| Token | 可观测且有请求上界的调用遵守现有 40,000 已报告 Token 运行预算；有 attempt 记录时列各阶段已知下界与未知调用数，无记录时阶段分布为未知；完整总额不明时为 N/A | 降低无效调用与重复上下文；未知计费或 baseline 缺用量时不报费用硬上限及相对节约 |
| 规划与工具 | 30 步、五次无进展上限；每次记录重试、无效动作、重复 URL、失败分类 | 将已证实项目故障降到 0；外站/网络问题保留原样分类 |
| 取消/清理 | queued/running/终态竞态无重复 `task_finished`；浏览器与客户端关闭 | 通过压力重复测试观察长期资源占用，再决定是否设数值 SLO |

时间、Token 和步骤上限来自 [`AgentLoop`](../../adaptive_agent/agent_loop.py) 的当前默认值；现有总 Token 是供应商已报告值，不等于无法观测的实际计费量。供应商未提供 usage 时完整总额记 `null`，另列可得的已知下界与未知调用数；无请求级元数据时后者也记未知，不填零或宣称费用硬上限。P95 对九次回归与三次留出分别作描述；需同时公布每次值、测试机器、模型、浏览器版本、网络窗口和样本数。若每题恰好只有 2/3 完整成功，九次 ≥90% 字段覆盖仍要求失败样本有可核实字段；这是已批准设计中的严格放行门槛，尚未经真实运行验证。

## 5. Go/No-Go 清单

| 检查 | Go 条件 | 当前状态 |
| --- | --- | --- |
| 设计 | Gate 1 文档和 ADR 已获用户明确批准，关键差异同步 V1 权威契约 | **PENDING** |
| 范围 | 所有 P0、批准的 P1 有需求 ID、追踪测试及验收，延期项未混入 | PROPOSED |
| 工程 | 当前提交的 CI、回归、安全审查均通过；没有未解释 P0 缺陷 | UNVERIFIED（针对未来提交） |
| 真实业务 | B01–B03 九次满足每题 ≥2/3；独立 G01–G03 至少 2/3；十二次完整保留 | **NO-GO**（历史 D7 为 0/3 UI 成功；新批次未运行） |
| 证据质量 | B01–B03 至少 68/75，独立泛化字段单列；结论来源追溯/准确 100%，所有失败公开 | **NO-GO**（历史无合格引用报告） |
| 部署演示 | 本机环境、启动/关闭、隔离 SQLite、错误/取消/重启路径可重复 | 待新基线验证 |
| 外部发布 | 若将来要公网/多用户，需独立安全和部署 ADR | **不在本轮范围** |

任一最低条件失败即 **No-Go**。提供方余额不足、站点变化、网络不可用也如实记失败或未验证，不能用离线 Fake 运行替代。Gate 1 仅获设计冻结批准，Gate 2 执行还需单独授权；Gate 2 完成后仍需用户验收，不能由 PR 合并自动推定业务完成。

## 6. 本机交付、演示与恢复

目标环境为**可信本机单用户、公开技术资料**：Python `>=3.12,<3.14`、`uv` 锁定环境、Node 22、Chromium、本机 SQLite、服务端环境变量注入 DeepSeek 密钥。现有 trace 会持久化有界 `ToolResult.content`，已知密钥替换不等于任意敏感网页脱敏；演示不得输入私人凭据或浏览私有数据。启动前检查锁文件/依赖、密钥存在、数据库可读写、浏览器可启动；演示时先从 Vue 提交 B01–B03，保留任务 ID、SSE 时间线、事实来源和真实报告，再演示取消、失败及重启后查询。命令细节以 [README](../../README.md) 与最终经验证的部署记录为准，不在未运行状态下声称可复现。

进程异常退出后的未完成任务按现有持久化逻辑标 `server_restart`，根据已有事实成为 `partial` 或 `failed`，并保留事件与报告；**不提供断点续跑**。回滚单个 Gate 2 PR 时回退该 PR 的代码/配置，保留用户 SQLite 和历史 benchmark；若包含数据库增量变更，须先说明可读旧数据、备份、正反向兼容和恢复演练。不得删除或覆盖已有 SQLite。上线范围只到本机可演示；公网部署需另做鉴权、SSRF、浏览器隔离与数据分租户设计及批准。
