# ADR-0001：保留模块化单体并定点提升真实任务成功率

状态：**APPROVED（设计）— Gate 2 未授权** · 冻结日期：2026-10-18 · 关联：[架构](../02_SYSTEM_ARCHITECTURE.md)、[Gate 0](../10_CURRENT_STATE_AUDIT.md)

## 背景

当前 Vue→FastAPI→ResearchService/进程内 TaskManager→AgentLoop→工具、SQLite 与 SSE 已形成业务骨架；r12 的 18 次真实尝试及三次 UI 验收均未完整成功。已核实 Planner 重复构造上下文与严格证据准入规则，但尚无调用级证据能把真实失败归因于单一模块。开发资源约每周 10–15 小时、四周 40–60 小时，目标是可验证的技术调研能力，而非框架/服务数量。

## 决策

选择 **方案 A：维持单进程模块化单体与六路 API、SQLite、现有领域事件/Reducer，按失败证据定点优化**。保留 Adapter 对 browser-use 的边界和 TaskManager 进程内并发上限。先补安全的阶段用量与失败诊断，再重放 r12 证据、修复重复上下文和真实误拒，最后完成 B01–B03 的真实端到端验收与 UI 证据展示。重启仍以持久事实终结，不承诺断点续跑。仅面向可信本机演示。

## 比较与理由

| 方案 | 收益 | 成本/风险 | 结论 |
|---|---|---|---|
| A 模块化单体 | 最大复用、事务和测试边界已在；可把时间用于 0% 完成率 | 无跨进程扩展与断点恢复 | 推荐 |
| B 单独 Worker | 可隔离浏览器/模型负载 | 需跨进程队列、取消、SSE 通知与部署故障处理；当前未测出 API 饥饿 | 暂缓，达到容量证据再立 ADR |
| C LangGraph | 节点 checkpoint/恢复与编排可用 | 状态/事件双轨、工具副作用重放、迁移及回归成本；不能自动解决事实准确性 | 不采用 |

[LangGraph 官方文档](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph)用于理解 checkpoint 取舍，不作为当前代码能力证据。Stagehand、Skyvern、Dify 的可借鉴点见 [Gate 0 对照表](../10_CURRENT_STATE_AUDIT.md#6-外部项目对照截至本次查阅)。

## 后果与约束

- 一个 API 进程最多执行配置上限内的任务；多进程部署不受支持。SQLite 事务轨迹是持久化事实，内存订阅队列只唤醒。
- 保留领域/DTO/ORM 分层与唯一浏览器适配边界；不向 `browser-use` 注入项目研究政策，不增加泛化框架。
- 分阶段用量作为既有事件的 **PROPOSED 可选字段**，须同步更新严格的 Reducer payload 校验及旧事件兼容测试；不新增路由或表。若真实诊断证明需要 schema 迁移，再单独提出并保护历史 DB。
- 安全前置验证不足以支持公网开放；真实重定向与地址隔离经受控测试前维持本机可信环境。
- 若 Gate 2 实测瓶颈或可靠性要求发生变化，提交新 ADR 和迁移/回滚证据，不暗改本 ADR。
