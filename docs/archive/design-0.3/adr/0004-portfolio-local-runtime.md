# ADR-0004：本机作品运行时与两周退出关口

- 日期：2026-10-19
- 状态：**SUPERSEDED TARGET — 未实施**；后续目标由 [ADR-0005](0005-windows-worker-wsl-postgres.md)决定。本 ADR 的原取舍保留供历史复查。
- 当前权威：[规格](../../../SPEC.md)、[计划](../../../PLANS.md)、[契约](../../contracts/CURRENT_CONTRACTS.md)、[评测协议](../../evaluation/CURRENT_EVAL_PROTOCOL.json)。[ADR-0003](0003-langgraph-postgres-lan.md)及其旧目标作为历史设计保留。

## 背景与取舍

r12 的 18 次尝试无完整成功，三次独立 UI 任务也未形成合格报告。现有 FastAPI/AgentLoop/SQLite/SSE 已有实现和离线测试，但账户隔离、崩溃恢复与双任务容量未经验证。作品首先要证明公开技术研究的任务成功、证据质量与按调用诊断能力，时间只有 8–12 周兼职、Windows 11 单机 16 GB，新增真实运行预算低于 300 元。旧目标的局域网部署和旧 SQLite 导入不服务首版本机面试演示，推迟且不以旧文档写入为采用理由。

最小可行备选为现有 AgentLoop + 同机 SQLite 持久队列 + 单进程 API/执行：迁移少、排障快；SQLite WAL 允许读写并发但仍只有一个写者，双运行下的竞争必须实测。[SQLite WAL 官方文档](https://www.sqlite.org/wal.html)。本次先尝试独立 Worker + PostgreSQL + LangGraph，因为进程故障隔离、队列行认领、检查点能形成可展示的工程纵切；这些机制不会自动提高研究成功率，也会消耗迁移、运维与调试时间。[PostgreSQL 行锁](https://www.postgresql.org/docs/current/sql-select.html)和[LangGraph 检查点](https://docs.langchain.com/oss/python/langgraph/checkpointers)是机制依据，不是本机容量或恢复成功的证据。

## 决定与退出条件

P-01 两周内只用离线假任务验证纵切，测 CPU、内存、磁盘、API/SSE 响应和双运行八排队。每个组件独立裁决，保留六路 API、账户/事实/事件契约与正式评测口径；关口失败时记录后续 ADR 和实际证据，再更新现行契约，不继续无界迁移。

| 组件 | 采用条件 | 未通过时的替代与退出 |
| --- | --- | --- |
| 独立 Worker | 提交后持久、唯一认领、取消/终态事务裁决、已提交事件补读；API 和 Worker 分别重启不丢任务 | 同机单进程持久队列，保留同一任务及事件契约；记录进程故障的限制 |
| PostgreSQL | 应用表与检查点职责分离；模拟双运行八排队无丢失、重复终态或不可接受的 16 GB 主机资源占用 | SQLite WAL 持久队列，实测并公开单写者竞争、恢复与容量限制 |
| LangGraph | 状态可序列化；一次恢复探针能重建浏览器并重新观察/规划，不重放结果不明的动作 | 保留现有 AgentLoop，以应用持久状态实现相同故障语义；不伪称检查点恢复 |

应用表是账户、owner、任务、事实、报告、尝试、费用和用户事件的权威；检查点仅负责执行恢复。每任务至多一次自动恢复，第二次故障诚实终结；SSE 从已提交事件按 ID 补读。研究质量阶段 P-02 优先于继续框架迁移。五账户含管理员，双运行八排队仅模拟；一次加密离线介质备份/恢复不等于持续灾备。

## 后果与未验证项

首版仅本机入口。局域网 HTTPS、浏览器 DNS/重定向/弹窗/子资源私网阻断、真实五人并发、长期备份保留与恢复、真实研究成功均须分别实证，不能从 P-01 离线纵切推断。若架构回退导致任何既定验收项无法满足，保持 No-Go 并向用户提出范围或资源再决策，不暗降门槛。旧 SQLite/r12 原件只读且不导入新 UI，旧结果不改写。
