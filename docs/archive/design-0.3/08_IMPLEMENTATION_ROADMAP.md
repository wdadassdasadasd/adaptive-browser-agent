# 四周增量开发路线图

> 状态：**APPROVED（设计）**；Gate 2 执行未授权。本文件将后续开发拆成约 **57 小时 / 四周**的十个小型任务；不是已完成的工作。每周按 10–15 小时估算。依赖 [PRD](01_PRODUCT_REQUIREMENTS.md)、[架构](02_SYSTEM_ARCHITECTURE.md)、[契约](04_DATA_AND_API_CONTRACTS.md)与[验收基线](06_ACCEPTANCE_AND_RELEASE.md)。用户只批准设计冻结，任何 G2 任务均须另获执行授权。

## 1. 顺序、容量与停线

| 周 | Task ID | 目标 | 工时 | 阶段验收 |
| --- | --- | --- | ---: | --- |
| 1 | G2-00、G2-01、G2-02；G2-09 协议预注册 1 h | 权威迁移、调用级失败证据与分阶段用量/失败分类 | 2 + 5 + 6 + 1 = 14 | 先消除 V1/目标设计权威冲突；可以解释 D7 症状，仪表不暴露秘密 |
| 2 | G2-03、G2-04 | Planner 上下文/无效重规划、事实证据路径 | 7 + 7 = 14 | 离线回归证明目标故障得到修复，不能仅以 Token 降低宣称成功 |
| 3 | G2-05、G2-06 | 终态/取消/资源一致性，B01–B03 真实闭环 | 7 + 7 = 14 | 三类任务得到真实、带来源报告或明确失败；形成是否继续放行的证据 |
| 4 | G2-07、G2-08、G2-09 余下 6 h | 证据诊断 UI、交付配置、新版评测与演示 | 5 + 4 + 6 = 15 | 当前代码指纹的工程检查与十二次业务验收可核验；Go/No-Go 记录 |

优先级：G2-00..09 均为 **P0 放行依赖**，第 4 周排期不降低 G2-07 的 FR-003/004/007 展示要求、G2-08 的 NFR-005 工程门禁或 G2-09 的真实验收优先级。G2-08 中的 PR/Bug 模板属可裁剪的流程建议，不能替代 CI 与契约检查。FR-008 模板/导出属于 P1 Should Have；只有 P0 真实任务达到放行条件且仍有容量时另立小任务，不能挤占 G2-06/09。RAG、MCP、Multi-Agent、LangGraph、Redis/Celery、PostgreSQL/Alembic、视觉模型和模型路由为 **P2/Deferred**，四周内不实施。若第 3 周真实完成率仍为零，优先延长定位与修复；第 4 周展示应如实保持 No-Go，不以 UI 工作掩盖失败。

所有任务按 [AI Coding 流程](07_AI_CODING_WORKFLOW.md)执行 `Issue → Evidence → Design → Plan → Test → Implement → Review → Verify → PR → Acceptance`。每个 PR 只覆盖一个相对独立目标；下列文件是**预期影响范围**，实际修改前需依据当时源码和批准契约确认。小改动选最小充分测试，不机械执行付费评测。真实模型测试、外部 PR/提交/发布须另获相应授权。

## 2. 任务卡

### G2-00 — 权威契约迁移（第 1 周，2 h，P0）

- **对应需求 / 依赖**：FR-001..007、NFR-005；依赖用户最终设计冻结批准及对本任务所列 V1 文件范围的明确授权。此任务只改文档，不改业务代码。
- **目标 / 方案**：按[设计索引的迁移规则](00_DESIGN_INDEX.md#权威关系与批准记录)为 `AGENTS.md` 加简短版本指针，在 `V1_SPEC.md`、`V1_CONTRACTS.md`、`V1_TEST_MATRIX.md` 添加有日期的前瞻差异指针/附录；保留历史 V1 文本、D7 报告与 r12 原件。逐项标清当前实现和获批目标，G2 行为 PR 只引用批准的 Task ID。
- **预期文件**：`AGENTS.md`、`docs/specs/V1_SPEC.md`、`docs/contracts/V1_CONTRACTS.md`、`docs/testing/V1_TEST_MATRIX.md` 的最小附录/指针；本 Gate 1 不修改这些文件。
- **测试 / 验收**：做链接/版本/权威优先级静态检查，抽查六路 API、六状态、四表仍在目标文档一致；`git diff` 不得出现历史正文、评分或原始记录改写。满足 AC-N05 的文档前置条件；若文件修改权限未获批准，保持 V1 权威并暂停行为 PR。
- **风险 / 回滚**：历史文档被误改。逐文件审查差异；回滚仅撤销新增指针，不重写旧结论。
- **DoD**：审查记录有冻结版本、批准范围、生效日期和每处新旧条款映射；没有未解释冲突，才解锁 G2-02..06 的行为变更。

### G2-01 — D7 调用级失败复盘（第 1 周，5 h，P0）

- **对应需求 / 依赖**：FR-002、FR-003、FR-007；NFR-002、NFR-004；依赖另行 G2 执行授权及现有 r12/D7 脱敏记录，不依赖代码变更。
- **目标 / 方案**：逐 run 对齐 Planner、Evaluator、结构化修复、Reporter 调用和事件用量；区分 `token_budget`、`no_progress`、`execution_error` 的直接触发、上游返回与未观测部分。产出可复现的最小故障路径与修复优先序，结论按 VERIFIED/INFERRED 标注；不把聚合指标推断成单一根因。
- **预期文件**：`docs/audits/` 的新诊断报告；必要时在 `tests/` 增加可复现夹具，不改 r12 原件。
- **测试 / 验收**：校验 18 条 run ID、三次 UI 任务 ID、事件序列与用量总和；将每项 P0 候选故障映射到失败先行测试或明确写出证据缺口。满足 AC-002/003/007 的诊断前置条件。
- **风险 / 回滚**：脱敏记录缺调用级内容时不可补造；停止归因并在 G2-02 增加安全观测。回滚仅撤销新诊断文本/夹具，不触碰历史批次。
- **DoD**：报告列出症状、触发点、证据路径、置信状态、下一步和无法验证处；经第二人或有效只读审查复核。

### G2-02 — 分阶段用量与失败分类（第 1 周，6 h，P0）

- **对应需求 / 依赖**：FR-007；NFR-002、NFR-004；依赖 G2-00 与 G2-01 的观测缺口。
- **目标 / 方案**：在 Provider 每次请求（含技术重试和独立结构化修复）的内部安全计量边界捕获阶段、已报告 Token、未知用量标记和耗时；按[04 契约](04_DATA_AND_API_CONTRACTS.md#4-事件-payload事务与重启)写入既有事件的可选增量。只用单一路径累加已报告 Token，不把修复再次计入父阶段；完整总额在有未知调用时为 `null`，已知下界单列。不持久化 Prompt、页面正文或凭据；不默认加表或新路由。
- **预期文件**：`adaptive_agent/agent_loop.py`、`adaptive_agent/llm/base.py`、`adaptive_agent/llm/deepseek.py`、`adaptive_agent/state_reducer.py`、`adaptive_agent/events.py`、`backend/services/persistence.py`、相关 `tests/`；实际最小文件集以失败先行测试确定。
- **测试 / 验收**：Fake Provider 覆盖正常、一次修复、首次已知但修复未知、无响应重试、不支持 attempt 的 Provider、旧 trace、预算边界；有请求记录的事件阶段已知量与现有增量对账，无记录时省略阶段分布而保留已报告总量；未知调用不被计零，脱敏扫描。满足 AC-007、AC-N02、AC-N04。
- **风险 / 回滚**：重复记账或事件 payload 兼容性破坏。先加兼容读取回归；回滚新增元数据字段，不改旧历史行、不删除 SQLite。
- **DoD**：故障样本可按 task_id/event_id 复盘到阶段，相关测试通过并有明确缺失值语义。

### G2-03 — Planner 上下文与无效重规划（第 2 周，7 h，P0）

- **对应需求 / 依赖**：FR-002、FR-007；NFR-001、NFR-002；依赖 G2-01/02 的调用证据。
- **目标 / 方案**：针对被证实的上下文重复、无效动作或重复规划路径做局部修复；复用 `ContextManager` 已有裁剪，保持 Observe→Plan→Validate→Execute 边界。先写真实症状的失败先行 Fake 回归，再最小化 Prompt/上下文或调整有界重规划；不重写 AgentLoop。
- **预期文件**：`adaptive_agent/planner.py`、`adaptive_agent/context_manager.py`、`adaptive_agent/prompts/planner.py`、`adaptive_agent/agent_loop.py`、相关 unit/integration tests。
- **测试 / 验收**：同一输入下比较调用次数、上下文大小、无效动作数与最终状态；长页面、重复 URL、非法动作及无进展边界回归。满足 AC-002、AC-N01/02；不以早停降低步骤冒充效率。
- **风险 / 回滚**：裁剪过度使事实丢失。保留已验证事实和当前观察的断言；回滚单 PR 逻辑，保留诊断事件。
- **DoD**：目标故障回归由红转绿，原有 AgentLoop/预算测试仍过，差异有调用级证据。

### G2-04 — 事实证据拒绝路径（第 2 周，7 h，P0）

- **对应需求 / 依赖**：FR-003、FR-004；NFR-001；依赖 G2-01 证据，尽量与 G2-03 分文件 PR 串行处理共享运行时。
- **目标 / 方案**：先确认[Evaluator 已有的证据片段匹配](../../adaptive_agent/evaluator.py#L127)在 r12 中是否误拒，再针对可复现的主体/URL 归属或去重丢失做最小修复；新增不含候选正文的步骤级拒绝数量/原因码，混合准入时也有诊断。报告只能引用已存事实，不倒填历史事实或降低可信度门槛。
- **预期文件**：`adaptive_agent/evaluator.py`（内部 `EvaluationOutcome`）、`adaptive_agent/agent_loop.py`、`adaptive_agent/state_reducer.py`、`adaptive_agent/reporter.py`、`tests/unit/` 与 `tests/integration/` 对应测试；保持 LLM 使用的 `EvaluationResult` schema 不含受信任诊断字段，避免无需求改动事实 ORM。
- **测试 / 验收**：官方来源有效/缺失/交叉主体/重复/冲突及同一步混合校验各有回归；候选验证通过数与证据拒绝数对账，重复事实另由 Reducer 去重、不算证据拒绝；trace 无候选正文，SQLite fact 与报告来源对账。满足 AC-003/004；不得通过改旧 benchmark 计分口径制造成功。
- **风险 / 回滚**：放宽匹配造成虚假事实。来源核验不通过即回滚该 PR，并保留失败记录与测试。
- **DoD**：真实故障的最小回归由红转绿；无根据事实仍被拒，报告结论可追踪 fact ID。

### G2-05 — 终态、取消与资源一致性（第 3 周，7 h，P0）

- **对应需求 / 依赖**：FR-001、FR-005、FR-006；NFR-001、NFR-006；依赖 G2-02，G2-03/04 稳定后集成。
- **目标 / 方案**：核查取消与自然完成、超时、数据库事务及重启的竞态，并补齐 queued 已提交但 `TaskManager.submit` 抛错的补偿终态；只对可复现缺陷做最小修复。维护唯一 `task_finished`、终态不可逆和浏览器/HTTP/订阅者资源所有权；重启仍按 `server_restart` 终结，不引入断点续跑。
- **预期文件**：`adaptive_agent/runtime/task_manager.py`、`adaptive_agent/agent_loop.py`、`backend/services/research.py`、`backend/services/persistence.py`、对应 integration tests。
- **测试 / 验收**：queued/running 取消、取消与完成同时发生、提交调度失败补偿、事件写入失败回滚、SSE 游标校验/订阅/首次补读竞态、重启数据库重读、资源关闭计数。满足 AC-001/005/006、AC-N01/N06。
- **风险 / 回滚**：跨层并发修复扩大范围。把复现测试和最小代码改动分 PR；回滚逻辑时保留测试及用户数据库。
- **DoD**：重复竞态测试无双终态或泄漏；状态/事件/报告事务一致，失败原因可见。

### G2-06 — B01–B03 真实闭环修复与 E2E（第 3 周，7 h，P0）

- **对应需求 / 依赖**：FR-001..FR-007；NFR-001..NFR-004；依赖 G2-03/04/05，真实测试需要单独费用授权。
- **目标 / 方案**：用固定 B01–B03 从 Vue 发起独立真实任务，检查官方证据、Agent Loop、SQLite、SSE 与报告；对仍失败的具体原因建立回归并拆出下一小 PR，不在验收中现场大范围重构。
- **预期文件**：`tests/` 中必要的 E2E/回归夹具及新验收记录；若定位出故障，仅在批准范围内修改对应 `adaptive_agent/` 或 `backend/` 文件。
- **测试 / 验收**：三类单次诊断运行保留全部原始结果、逐结论核源；同时复测取消、失败和重启。此任务用于发现并消除阻断，**不能用三次单跑替代 G2-09 的九次放行样本**。满足 AC-001..007 的真实链路证据。
- **风险 / 回滚**：模型/站点漂移或费用耗尽导致未知。保留每次失败和环境记录；禁止修改旧 r12 原件或临时放宽评分。代码回滚按导致失败的独立 PR。
- **DoD**：三类任务各有可复盘完整链路；未完成项有明确分类与下一 Task ID，不能声称已放行。

### G2-07 — 证据与诊断 UI（第 4 周，5 h，P0 放行依赖）

- **对应需求 / 依赖**：FR-003、FR-004、FR-005、FR-007；NFR-004；依赖 G2-02、G2-04/06 的真实数据契约。
- **目标 / 方案**：在现有任务详情和 trace API 基础上显示事实证据卡片、来源链接、执行时间线、阶段 Token/耗时与失败原因；Loading/Empty/Error/Partial/Success 均从真实响应推导。沿用六路 API；若现有 DTO 不足，先提出兼容扩展并按批准契约实施，不造假成功状态。
- **预期文件**：`frontend/src/App.vue`、`frontend/src/api.ts`、`frontend/src/App.test.ts`，必要的 `backend/schemas/research.py`/API 适配。
- **测试 / 验收**：前端交互测试覆盖断线补读、无来源、partial、失败、取消与指标缺失；人工从真实任务 ID 对照页面与 SQLite。满足 AC-003/004/005/007。
- **风险 / 回滚**：事件 payload 细节泄漏或旧任务兼容性。旧任务无新诊断字段时显示未记录；回滚 UI 渲染而非数据。
- **DoD**：页面每项结论能打开来源，数字与事件一致，所有空/错/部分状态清晰。

### G2-08 — 工程交付配置（第 4 周，4 h，P0 放行依赖；模板可裁剪）

- **对应需求 / 依赖**：NFR-003、NFR-005、NFR-006；依赖 Gate 1 的配置审计与批准，无业务代码依赖。
- **目标 / 方案**：只补真实缺口：简短 AGENTS.md 设计读取条件、PR/Bug 模板、README 本机启动/恢复、必要 CI 权限或检查；复用现有 Python 3.12/3.13 + uv、Ruff/pytest、Node 22 前端检查。GitHub 分支保护与 Required Checks 属外部设置，另经授权；不新增 Redis、MCP 或 Skill 框架。
- **预期文件**：`AGENTS.md`、`.github/` 模板/现有 `ci.yml`、`README.md`；具体范围以 [AI Coding 审计](07_AI_CODING_WORKFLOW.md)批准项为准。
- **测试 / 验收**：检查 YAML、锁定安装、Python/前端命令和 secret 扫描；PR 模板要求需求 ID、测试/风险/回滚。满足 AC-N03/N05/N06。
- **风险 / 回滚**：CI 工作流变更误阻断 PR。先保持离线、最小权限；失败时回滚该配置 PR，不删除历史记录。
- **DoD**：当前代码的实际 CI run 通过且可点击，交付文档经本机复现，未加入无需求配置。

### G2-09 — 新版评测与演示 Go/No-Go（第 1 周预注册 1 h、第 4 周 6 h，合计 7 h，P0 放行依赖）

- **对应需求 / 依赖**：FR-001..FR-007、NFR-001..NFR-006；第 1 周协议预注册依赖 G2-00；真实执行依赖 G2-06、G2-07/08 与单独模型费用授权。
- **目标 / 方案**：第 1 周锁定新协议、B01–B03 字段键和 G01–G03 留出原文；第 4 周稳定代码指纹后跑 B01–B03 每题三次及 G01–G03 各一次 full-system 真实 UI 业务验收，保存十二次脱敏原始记录和逐项官方来源核验。7 h 仅是链路已稳定、评分脚本与核源表可复用条件下的初估；若运行、核源或阻断修复超时，保持 No-Go 并重排，不压缩样本或剔除失败。可另跑三组对照，但需完整新批次并说明 baseline Token 预算不匹配。
- **预期文件**：`docs/audits/` 新验收报告、`data/benchmark/` 新版本独立目录（仅在授权的实际运行中）、必要的评测脚本或测试；**不修改** r12 原件、旧评分和 V1 历史报告。
- **测试 / 验收**：逐次核对任务 ID、终态、报告、SQLite、SSE、来源、字段；B01–B03 每题 ≥2/3、合计 ≥68/75 字段；G01–G03 单独 ≥2/3；实质结论来源追溯/准确 100%。列出 Token、平均/P95 耗时、重试、重复 URL、失败类别与缺失值。满足 [Go/No-Go](06_ACCEPTANCE_AND_RELEASE.md) 方可提交业务验收。
- **风险 / 回滚**：公开站点变化、供应商费用与不足样本使结论不稳定。所有失败原样保留，未达标标 No-Go；评测数据不回滚不覆盖，后续修复必须新代码指纹和新批次。
- **DoD**：完整十二次记录、人工核源与重算脚本/报告一致，回归与留出结果分开，工程/业务/质量三层均明确 Go 或 No-Go，用户最终验收有可审阅证据。

## 3. 变更控制

每项任务开始前写 Issue、固定对应 FR/NFR、核对现有源码与受影响契约；必要失败回归先行。每个 PR 记录实际修改、测试命令与输出、未运行项、已知风险及数据回滚方法。若修复要求变更冻结 V1 行为或 Gate 1 目标架构，先提出新 ADR 并取得批准，再同步设计、契约、测试与追踪矩阵。四周投入是估算，不因排期到期而降低来源核验或隐藏未完成任务。
