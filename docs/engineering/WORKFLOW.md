# G0–G7 工程执行流程

本页负责项目内的阶段顺序与关口，不另立产品、API 或评测门槛。权威顺序见根 `AGENTS.md`；重要任务从[任务模板](TASK_TEMPLATE.md)建立唯一记录，小修可在任务说明或 PR 中记录必要证据。共享 `engineering-workflow` 只选择本流程；本流程按需调用领域 Skill，领域 Skill 不回调共享入口或另建任务。直接从本页开始也可完成最低项目流程。工作开始与结束均检查 Git 状态、证据和未完成事项。

| 关口 | 输入 → 动作 → 可核验输出 | 停线／人的决定 |
| --- | --- | --- |
| G0 审计 | 现行四入口、V1 行为、源码、状态和历史证据 → 区分现有／目标／历史 → 基线、风险、保留及迁移映射 | 缺证据标未知，不改写历史。 |
| G1 产品定位 | 用户提出问题与约束 → AI 研究用户、替代方案、价值假设与成本并持续澄清 → 定位、成功标准、范围、非目标与待验证假设 | 用户决定产品定位；上游 Star 不代替实测。 |
| G2 架构与数据流 | 已批准定位、ADR、现状 → AI 比较候选，设计模块职责、接口、数据／状态归属、关键数据流与失败路径 → 设计图、决定和迁移范围 | 重要设计先独立技术审查，再由用户讨论批准，之后实施；新增依赖另需授权。 |
| G3 需求设计 | 已确认目标与架构 → Requirement／AC、API／状态／数据边界、异常和非目标 → 可测 Spec／契约 | 用户确认行为边界与优先级；重要契约、状态、权限、费用或事实变化先完成设计审查与批准。 |
| G4 模块与任务计划 | 业务需求／AC → 映射模块职责、依赖和实施顺序 → 有独立验收价值的任务、里程碑、检查与 No-Go | 用户确认实施范围和里程碑；任务过大则拆分，缺独立验收价值则合并；付费点单列。 |
| G5 模块开发 | 已批准任务与基线 → 最小实现、风险驱动 TDD、自检、独立 Review、核实发现后修复重测复审 → 完整任务 Diff 和证据 | 批准范围内连续修复测试失败并在里程碑汇报；新增范围、重要设计变化、里程碑业务验收失败或权限／费用变化交用户决定。 |
| G6 测试与业务验收 | [测试策略](../testing/STRATEGY.md)、需求与轨迹 → AI 准备可运行结果、检查证据、验收步骤和未知项 → 技术结论与用户关键业务验收结论 | 用户亲验关键业务行为；真实浏览器诊断和每次付费调用分别授权，失败样本保留。 |
| G7 PR 交付 | 可审阅验收包 → 获授权后暂存／Commit／Push／创建 PR → CI、Review、回滚与交付记录 | 用户看过结果后授权本次提交操作；明确命名的操作可一次授权，合并／发布另行决定；远端门禁以实际结果为准。 |

**按任务展开**：普通 Feature 从已批准需求／任务进入 G5，不重复产品和架构关口；定位不明则回到 G1，架构／数据流变化走 G2。Bugfix 从现象／影响、复现或可靠轨迹、根因和回归测试进入最小修复；不能复现时标证据不足。非语义小改自检并运行适用检查；普通行为变化增加一名独立上下文审查；高风险选择相应专业视角，安全边界必须安全审查。专项审查若已覆盖正确性可承担通用独立审查，不机械叠加角色。共享 Skill 或自定义角色缺失时用可用的独立审查方式；无法取得独立上下文则标审查未完成。

**Review 与修复闭环**：交付原始需求／AC、适用规范、目标分支／基点、任务归属路径、完整 Diff（已提交＋暂存＋未暂存＋任务新增文件正文）及实际检查结果。记录基点、版本和内容快照或指纹，审查期间固定相关内容；新上下文不继承实现者的推理或预设结论。核对需求符合性、正确性、失败路径、兼容与重要测试缺口；发现须有文件／行、触发、影响和证据，机械格式交给工具。核实后修复，重跑受影响检查；行为变化独立复审，范围或跨模块假设改变时复审完整任务。相同内容的暂存／提交不使审查失效，新增行为、上游变化或 CI 修复需补审。反复暴露同一设计问题时重新评估设计并请用户作具体决定，不无限追加补丁。

**Agent 评测**：离线模拟、诊断 Pilot、正式批次分别标识；正式协议只由 `docs/evaluation/CURRENT_EVAL_PROTOCOL.json` 决定。每次记录版本、运行 ID、调用与事实、来源、人工核源、报告哈希、实际／未知 Token 和费用。失败按 Planner、工具、来源、Context、Memory、LLM、Worker、预算、评测核查层分类；改变一个可证伪假设后先离线回归，再请求真实复测。单次改善只作描述，不主张统计显著性。

**切片执行**：负责人启动阶段后，从首个未完成片连续开发/测试/独审/修复至人工验收包；人验收和准确commit/push/PR授权后交付，必要CI通过自动下一片，同阶段一个分支和PR。阶段末合并另批，实际合并后人明确启动下一阶段。新增CI修复内容重新给受影响验收包及准确Git授权，已验行为改变须重验。首次暴露安全边界当片验证，缺必需证据不DONE；缺独立审查明确pending。阶段五资格受影响先补验、最新适用最低恢复先于5.4，额度不重领。
