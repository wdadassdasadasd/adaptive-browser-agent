# G0–G7 工程执行流程

本页拥有项目任务路由、开发闭环、停止条件与交付要求。共享 engineering-workflow 只路由一次，领域 skill 只补方法并返回同一任务。没有个人 skill 也直接执行本页；不另建编排或平行任务记录。

## 入口与规则归属

运行 `.\.venv\Scripts\python.exe scripts/dev_context.py` 获取有界索引，再核 Git、原始人工授权和受影响章节。索引不可用/过时则查唯一任务记录最新相关段；索引不检测工作区/配置漂移，也不证明许可或资格。已有有效授权不重复申请。

- 根 [AGENTS](../../AGENTS.md)：始终适用的边界及条件入口。
- [PLANS](../../PLANS.md)：阶段/切片依赖、推进条件、Git与人工验收时点。阶段一原始连续交付覆盖按该页及原文适用，模板的默认规则不能覆盖它。
- [SPEC](../../SPEC.md)／[功能AC](../features/DECISION-001/spec.md)：结果；[CURRENT_CONTRACTS](../contracts/CURRENT_CONTRACTS.md)：运行/权限/安全语义与参数。
- [唯一任务记录](../features/DECISION-001/tasks.md)：原始授权、动态状态和实际证据；重要任务复用[模板](TASK_TEMPLATE.md)，小修只记录必要信息。
- [唯一协议](../evaluation/CURRENT_EVAL_PROTOCOL.json)：涉及协议约束的实施、资格核验、配额、评测或真实执行（含沿用既有资格）读取适用段落；普通单测不触发研究评测。历史协议只解释原固定版本。

## 按当前任务进入关口

| 任务/关口 | 动作与完成条件 |
| --- | --- |
| G0 相关基线 | 只核任务相关的现有/目标/历史、源码、Git及证据；缺项明确未知，不重载整套历史。 |
| G1 定位、G2 重要设计 | 目标未定先研究/澄清；架构/数据流候选先独立技术审查，再由人批准。完成于明确决定或准确待决问题，不把研究当批准。 |
| G3 需求、G4 任务计划 | 已确认结果对应Requirement/AC、行为/失败路径、模块依赖、里程碑和验证；重要契约/状态/权限/费用变化先设计审查与人批准。 |
| G5 已批准功能 | 从现行任务/基线直接实现→针对检查→风险独审→核实修复及必要复审；不重开G1–G4。 |
| G5 缺陷 | 现象/影响与复现或可靠轨迹→根因定位→最小修复和能捕获原症状的回归→风险独审；证据不足明确披露。 |
| G5 非语义小改 | 完整任务差异自检与适用检查；R0不新增独审或大型文档。 |
| G6 验收/继续任务 | 核当前字节与已有证据，只补缺项；按[测试策略](../testing/STRATEGY.md)验证，准备可运行入口、人验步骤/预期、关键diff和未知项。 |
| G7 交付 | 按PLANS及原始准确授权核暂存范围、commit/push/阶段PR、实际CI；无授权则只准备包。合并另批，下一阶段须前阶段实际合并及明确启动。 |

选中方法后传递当前关口、已核原件和缺项；本任务已完成且仍有效的入口核对即满足 skill 对应的起步步骤，只补缺项或已漂移的证据。项目方法按证据选择：[research-implementation](../../.agents/skills/research-implementation/SKILL.md) 用于获准的业务实施，[agent-failure-triage](../../.agents/skills/agent-failure-triage/SKILL.md) 用于有实际 Agent 轨迹的故障，[research-eval](../../.agents/skills/research-eval/SKILL.md) 用于协议约束的资格/评测。普通测试失败按 G5 缺陷处理；非语义文档小改走 G5 小改。Spec Kit 的需求、计划、任务和验证仍用现有项目记录。

## 开发、验证与独审闭环

实施前在现有任务说明绑定AC→可观察行为→关键失败路径→证据；不为小修另造文档套件。跨模块变化优先检验上游最大合法输出能否适配下游、支持组合一致、遗漏/截断保持partial、失败诊断与资源清理。缺陷测试须覆盖原症状，测试数量不代替链路覆盖。首次暴露安全边界当片验；事务/并发须真实restrictedPg独立连接、进程语义须真实进程，Mock/skip不冒实际通过。适用检查通过后仅因新变化、失败或未解决风险扩大检查。

把相关跨模块检查落到同一条可跑的用例：由生产者生成边界输入，交给实际消费者，断言容量内结果、超界结果及遗漏如何到达对外状态。例如 1.1 冻结候选 05 的上游可生成 2048 项，检查应让这些项经过实际帧编码，覆盖 64 KiB 边界及截断后的 partial/诊断；只测各函数的短输入无法证明两者匹配。现有用例已覆盖则引用其证据；合成通过只证明所测组合。第二次同链失败，用现有结果先核容量、支持组合、partial、诊断和清理，并明确下一次真实操作会区分哪些仍可能的解释；无新增诊断价值时收拢证据，禁止把同质重试或扩域当成默认下一步。

| 风险 | 必需检查/审查 |
| --- | --- |
| R0 非语义可逆 | 完整任务diff自检及针对检查。 |
| R1 既有边界内行为 | 实施/测试后，一名新上下文独审。 |
| R2 架构、持久状态、并发/事务、认证授权、迁移、决策指导 | 重要设计独审→人决定→实施/失败验证→实施独审；已批准设计复用。安全边界需安全覆盖，合适专项可兼需求/正确性，不机械叠加角色。 |
| R3 不可逆/权限扩张/真实数据删除/发布 | 准确操作的人工授权；不由流程或阶段启动推定。 |

从同一份已冻结入口一次交办独审：原始需求/AC、约束、base/current revision、归属路径、完整任务committed/staged/unstaged diff、新文件正文与实际检查（含失败/skip）；混合文件区分本任务和无关差异。给可读取原件及指纹，新上下文不继承实施聊天或预设结论。要求审查者交回覆盖范围、阻碍及发现（优先级、文件/行、触发、影响、证据），覆盖需求适配、正确性、失败路径和关键测试缺口。核实后集中修复，重跑受影响检查，复审交原发现、行为/依赖差异与新结果；不变内容复用，相同字节暂存/提交不使独审失效。缺原件或无法独审记pending。

一个主实施者保持连续性。必需独审按上表安排；额外代理只在有独立产出、能缩短关键路径时交办，例如主线验证期间核固定版本的上游接口，或独立核失败覆盖。交办写清“问题、原件、路径/权限、交回证据、完成条件”；同一候选避免角色重复，审查上下文按上段隔离。发出后推进不依赖结果的工作；无其他工作用最长60秒可唤醒等待，不短周期追问。代理角色指令不创造OS只读隔离。

## 停止、记录与交付

批准范围内的本地诊断、测试和审查修复持续推进；只因重要未决设计、范围/费用/权限变化、需产品选择的验收失败或外部阻碍暂停受影响工作。先完成可做的本地准备，再请求具体缺少的决定/操作许可。阶段原始授权、配额与deadline不因恢复/换聊天重置。

按PLANS从本阶段首个未完成片推进；必要CI通过才继续同阶段，阶段末合并及下阶段另有门禁。每片提供可运行结果、逐AC状态、完整差异/独审身份、实际命令结果/skip/未知、风险/回滚、人验步骤及准确Git范围。缺必需证据不能DONE；提交、CI、技术验证、独审、人验、工程能力、效果/价值、Go/发布分开。效果评测显式按需，未运行记未评测；不减少工程必需验证或洗旧失败。Memory/Browser/私有祖先/unknown/恢复/资金等不变量见根AGENTS与契约，运行参数不在本页复制。

里程碑/交接时更新唯一任务记录EOF `dev-current`（<=6000 UTF-8字节/60行）；保持历史与原始授权/失败/候选指纹指针，后续追加使旧索引失效。常规实施/有界调查medium，复杂诊断/架构/安全/并发/恢复/独审high；分别核配置、角色、实际回合，不能热切换声明。1.1 需要新增磁盘语义、扩大支持域/限额、放宽校验或改变原名/祖先证明时，停在可审阅的设计决定，现有授权不自动覆盖。配置交付后回自然开发，无新证据不再泛化重构。

观察配置收益复用唯一任务记录里的现行采样口径：接下来三个自然、已授权任务，开工前登记边界、开始版本、风险/规模、父子日志位置和覆盖，冻结已有日志指纹，未来日志生成后补指纹。只从已固定的历史候选中事前登记匹配包或 `none_qualified`。记录完整回合区间并集、按响应身份去重的未缓存输入与输出、漏检/返工和验证缺口，缺项保留未知。风险、规模和覆盖可比，且必需 AC、独审、集成齐全、严重缺陷已关闭，才比较时间及 Token；否则只报告观察。配置改动、额外模型回合或历史补登记不充样本。
