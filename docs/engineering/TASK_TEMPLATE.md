# 单切片任务包模板

复制本页到获批准的重要 Feature／Bugfix 的唯一任务记录；小修可在 PR／任务说明中覆盖相同信息，不为每次微改创建大型文档。`PENDING` 表示尚无事实或批准，不表示通过。

| 字段 | 填写内容 |
| --- | --- |
| Task ID／Feature／Requirement／AC | 唯一 ID 和权威链接；分别记录实施状态 `PENDING`／`ACTIVE`／`IMPLEMENTED`／`BLOCKED`／`CANCELLED`，以及本次授权范围内的验收状态 `PENDING`／`PARTIAL`／`DONE`／`FAILED`。 |
| 用户价值与可观察目标 | 哪个用户问题消失；定位、范围、非目标与成功标准链接；如何实际看到完成。 |
| 依赖、优先级与批准 | Requirement／AC → 模块职责／依赖 → 任务顺序与里程碑；用户确认的范围。重要设计记录候选、独立审查与用户批准，费用／依赖授权分别引用。 |
| 范围与复用 | 预计文件、受影响调用链、可复用实现、本次禁止范围。 |
| 接口与状态 | API、Schema、事件、DB、权限、事实、费用或兼容变化；无则写“无”。 |
| 工作量与不确定性 | 理解、实现、测试、Review、修复的预计时间及最大未知。 |
| 基线与实施 | 改动前命令／退出码／已知失败；最小实现顺序及原件保护。 |
| 验收 | 正常、边界、失败、并发／幂等、资源清理、权限及回归；每项命令和预期结果。 |
| 实际证据 | 版本、每项 AC 的已验证／待验证判定、命令与退出码、测试输出、真实任务／fact ID／报告哈希、跳过项和原因。技术验证与人工业务验收分别记录；不得用 Mock 充当真实成功。 |
| 独立审查与修复 | 风险及审查者／专业范围、原始需求／AC、基点和内容指纹、完整任务 Diff（含已提交／暂存／未暂存／任务新文件）、实际检查。逐项记录发现、核实、修复、受影响复测与行为变化复审；不能独立审查时明确待完成。 |
| 业务验收包与里程碑 | 可运行入口、关键差异、用户操作步骤、预期结果、证据和未验证项；用户亲验关键行为的结论。批准范围内连续修复测试失败，遇重要设计／范围变化或里程碑业务验收失败请用户决定。 |
| 风险与回滚 | 未验证事项、No-Go 条件、兼容与安全影响、可执行恢复方式。 |
| PR 与交付 | 可审阅验收包及本次 Commit／Push／PR 操作授权、目标 PR／CI、最终内容与审查一致性、遗留问题；合并／发布另批，未执行标 `PENDING`。跨配置源与业务项目时分列版本、审查和交付范围。 |

代码提交条件：已核对暂存范围、实际运行与改动风险相称的检查，逐项披露未验证 AC 和跳过的检查；提交授权单独记录。任务验收 `DONE` 只表示**本次明确授权的范围**有可复查证据，新增失败已处理，关键风险已说明；若范围仅为离线切片，须写明“离线”，不可推断真实质量或产品 Go。正式放行另按现行阶段与冻结协议判定，未授权的真实或远端动作仍标 `PENDING`。
