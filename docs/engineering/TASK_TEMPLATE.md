# 单切片任务包模板

复制本页到获批准的重要 Feature／Bugfix 的唯一任务记录；小修可在 PR／任务说明中覆盖相同信息，不为每次微改创建大型文档。`PENDING` 表示尚无事实或批准，不表示通过。

| 字段 | 填写内容 |
| --- | --- |
| Task ID／Feature／Requirement／AC | 唯一 ID 和权威链接；状态 `PENDING`／`ACTIVE`／`DONE`／`BLOCKED`／`CANCELLED`。 |
| 用户价值与可观察目标 | 哪个用户问题消失；如何实际看到完成。 |
| 依赖、优先级与批准 | 前置关口、产品／架构／费用／依赖授权引用。 |
| 范围与复用 | 预计文件、受影响调用链、可复用实现、本次禁止范围。 |
| 接口与状态 | API、Schema、事件、DB、权限、事实、费用或兼容变化；无则写“无”。 |
| 工作量与不确定性 | 理解、实现、测试、Review、修复的预计时间及最大未知。 |
| 基线与实施 | 改动前命令／退出码／已知失败；最小实现顺序及原件保护。 |
| 验收 | 正常、边界、失败、并发／幂等、资源清理、权限及回归；每项命令和预期结果。 |
| 实际证据 | 版本、命令与退出码、测试输出、真实任务／fact ID／报告哈希、跳过项和原因。不得用 Mock 充当真实成功。 |
| 风险与回滚 | 未验证事项、No-Go 条件、兼容与安全影响、可执行恢复方式。 |
| PR 与交付 | 目标 PR、Review 发现及处理、授权与合并后记录；未创建则 `PENDING`。 |

完成定义：范围内 AC 有可复查证据，新增失败已处理，关键风险已说明，实际 Git 状态与交付记录一致；未授权的真实或远端动作仍标 `PENDING`。
