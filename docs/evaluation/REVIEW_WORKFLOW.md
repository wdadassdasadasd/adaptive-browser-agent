# 评测核源、计时及独立复核

执行规则只来自[唯一现行协议](CURRENT_EVAL_PROTOCOL.json)；[M1能力引用](DECISION_M1_PROTOCOL.json)不再定义另一套资金/Go。[连续记录](../features/DECISION-001/tasks.md)区分材料制备、技术验证、人工业务验收、价值和发布。此流程不授权模型/Browser/Tokenizer/数据库或购买。

1. 制备与冻结：独立读取六道准确题面、问题回答映射、完整接受条件、关键评分判据、等价工作量与剩余差异；同领域两题须有不同决定性调查问题，不能只换业务外壳。准备来源只证可调查，不是正式报告已核源。按原字节hash绑定材料→协议→能力引用；材料改动重新绑定和受影响复审。只向执行输入交付当前题和当前回答，scorer/其他题/来源参照不注入。
2. 资格：核实固定普通AI/独立DR/手工搜索引擎清单、免费额度及真实账号地域；确认版本、工具/Memory政策、授权grant、全账/unknown/在途/余额/实际币种与最坏覆盖、Tokenizer和备份资格。Browser不资格为0。任何缺失诚实pending，不以grant/支出上限当资金到账。
3. 注册与揭题：协议/材料身份固定后单次CSPRNG seed及完整分配算法/结果落记录，不重抽。无关材料健康检查先于揭题。首次显示准确题面即记录first_display_at并启动主动区间和24h墙钟；六次串行按已定顺序，batch14天。提前看题须记真实曝光/污染，不隐瞒、换题或把看题时间排出。
4. 运行与人工稿：按协议attempt_record_contract保存slot/case/method/run/owner/版本/Call与费用身份；连续主动区间含读题/澄清/提示交互/查源/阅读/整理/读审计缺陷/重写，区间不重叠、可重算总数。原始程序/DR输出不可变，所有人工提交revision保存parent/artifact SHA/编辑时间/主动区间引用。等待、审计劳动及行政准备另记，不把研究工作转成行政免计。linked Turn共享Case额度/原截止。
5. 核源：先确认本稿hash及接受revision→逐条全部硬条件和推荐/排除依赖关键主张→打开官方原文→核主体/发布者、精确版本/地域/适用时间、最小片段/定位及限定/反证→记录claim/fact/capture/URL/hash、核验人/时间/结论。结构引用/子串不证明语义；搜索摘要/供应商authority/旧核源不继承为当前真值。来源丢失、冲突、适用性未知不能以模型评委补判真实。
6. 审计：最多两轮缺陷反馈＋一次最终评分；反馈只缺陷类型与被审稿定位，绑定准确report SHA、reviewer/time/round。审计若实际查出新事实/候选或替写结论，披露贡献、时间和任何新增费用，不能称纯缺陷审计。本人实际补查/阅读/重写计主动；最终评分后不改稿替失败。最终六稿七维共同质量全过，才按恰好三对时间算中位≥20%；缺/零基线不得补120或改变分母。
7. 原始技术与失败：保存schema失败/partial/取消/故障/未执行/安全停线/unknown及停止原因，不因最终人稿合格改成功。Agent侧无外部AI代修/有意复制Control输出笔记；Control一DR/题不再生成替失败。新版本修复仅后续批次，正式失败不得用优化预留槽补。无赢家须证据充分覆盖已发现决定性替代，配额耗尽/未深查/全失败不算充分。
8. 重建与优化：canonical Call、source、claim、context、request、response、usage/费用和report关联完整；UI事件达到上限不删canonical记录。离线重建禁网络/Provider，不运行会再次外调的框架replay，缺坏工件not_reconstructible。优化预设目标、本人亲改、非退化AC、固定源离线与独立审查、另授权同条件复测全部留证；来源/模型漂移若影响症状不直接归因修复。至少真实纠正一症状，失败实验有效但不替代门槛。

## 证据、检查与交付

每attempt的必存字段和区间/稿件/审计关系以协议attempt_record_contract为唯一机读定义。artifact路径、原bytes SHA、缺失原因、私密访问控制、providerusage与费用未知分别记录；不把安全派生正文称原HTTP，也不收隐藏思维链。公开报告只安全引用/代码/计数，密码、cookie、API key、nonce与原敏感正文不进入日志。

本批validator只验证声明、schema/引用/原字节及部分算术；它没有新runner、计时器或费用写入系统，不能单凭exit0主张真实来源、账号权限、账单完整或价值通过。既有历史结果/ledger须显式固定Git commit/path/SHA及必要换行变换，命令见[评测入口](README.md)，`--historical-only`只给历史结论。旧执行入口对新协议的fail-closed检查先于Settings/client/engine/输出和写入。

最后保存完整task diff（含已提交/暂存/未暂存/新文件）、实际checks、正文hash和独立实际文件审查；核实发现后修复/复测/受影响复审。测试、AI独立审查、本人业务验收、个人掌握、省时价值、Go/发布分别裁决。当前真实尝试0，任何未来执行另授权。
