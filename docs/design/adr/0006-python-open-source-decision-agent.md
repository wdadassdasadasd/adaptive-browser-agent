- 日期：2026-10-23
- 状态：**已批准产品方向；2026-10-23 现行规格／契约已同步，离线业务开发获授权；能力尚未实现**
- 决策记录：[V3-PRODUCT-001](../../decisions/DECISION_LOG.md)
- 权威边界：[现行规格](../../../SPEC.md)、[计划](../../../PLANS.md)、[目标契约](../../contracts/CURRENT_CONTRACTS.md)、[冻结评测协议](../../evaluation/CURRENT_EVAL_PROTOCOL.json)仍约束当前开发；[ADR-0005](0005-windows-worker-wsl-postgres.md)继续约束运行架构。

## 背景与决定

当前 P-01 本机假任务通过，但 P-02 三题真实 Pilot 均未达到 full；报告器尚未实现有依据的条件化推荐。用户选择以 Agent 应用研发校招为目标，将产品面向**开发团队技术负责人**，首版限于**公开 Python 开源技术选型**。输入包括用途、必须满足的条件、偏好和可选候选；输出为事实支持的比较、未知／冲突和条件化建议。缺少决定性证据时诚实拒绝无条件推荐。

先修复已有研究事实与 Token 预算问题，完成现行质量关口，再实施决策输入、事实到条件映射和推荐。保留 Windows API、独立 Worker、WSL PostgreSQL 与现有 AgentLoop；应用表继续拥有任务、事实、调用、费用和事件。首版不自动修改依赖、创建升级 PR、推断用户代码库兼容性或引入新编排框架。

## 证据与代价

[岗位及竞品研究](../../research/AGENT_JOB_PRODUCT_FIT_2026-10-23.md)显示应用研发岗位需要真实任务、工具和评测闭环；Dependabot／Renovate 已覆盖依赖更新自动化。此方向复用现有九题与 Agent 工具链，但需为用户约束、fact ID 对应关系和条件化推荐新增契约与测试。当前九题的 15 次正式门槛、人工核源、费用总账保持不变；决策质量另行复核，不并入正式分母。

## 生效条件

[DECISION-001 需求细化](../../features/DECISION-001/spec.md)与[逐项映射](../../decisions/V3_SPEC_CONTRACT_CHANGE_PROPOSAL.md)服务于现行规格／契约，不能取代根规格。本轮“执行”授权相应离线业务开发；真实浏览器、付费模型、依赖安装、Git 写操作分别依仓库授权规则执行。若研究质量、资源或预算证据不足，保留 No-Go，不以新的产品名称改变历史结论。
