# DECISION-001：有证据的交互式技术选型

状态：PREP-BASELINE-v4.3 已明确批准，2026-10-27 同步限定文档；新实现及真实运行未授权。设计见 [ADR-0008](../../design/adr/0008-m1-engineering-baseline.md)，实际状态见 [任务表](tasks.md)。DEC-AC-01–07 原定义/历史证据保持；08–16 按本版澄清替代目标前提，新增17–20。原 ADR7 及验收工件保存旧版本，不能改写成新要求已通过。

## 用户、场景和边界

用户为开发应用且需依据公开资料作有限技术决策的开发者，首批本人及同学。触发是候选已有但约束不完整、资料分散或条件变化，需要可核查的短名单、排除理由及下一步验证。人工官方文档研究、通用 LLM 和研究报告是替代方式；是否真正节省决策成本仍待真实使用验证。首版不是无限范围聊天、自动部署/集成、音频效果评测或养老系统交付。

产品能力是条件提议/接受、有限研究、通用身份与角色、证据矩阵、失败/未知处理、历史与引用。任务输入是具体目标、候选、语言/设备/部署等约束；语音角色、ORM 的迁移要求和 PDF 的 Chromium 限制属于任务专属。通用工程机制是状态/调用/预算/记忆/投影；评测分组、冻结资料和人工评分是评测逻辑，不进入业务模块硬编码。

输入前提：本机认证用户、公开非敏感资料、明确接受条件或保留未知；研究需要代码/模型/资金前置和具体运行授权。澄清不强制填造答案，用户可编辑或接受提议。运行中改变条件先取消等终态，再以新 revision 提交；终态报告不覆盖。

## 旧研究入口的输入、输出与状态边界

本节及 DEC-AC-01–07 保持旧六路 API 兼容；新会话走独立命名空间及现行契约 V2 小节，不将旧 candidate_projects 数组或同任务 fact ID 规则直接放宽。

- 输入：现有 `goal` 请求保持兼容；目标契约增加**可选** `decision_context`，包含 `use_case`、`must_have`、`preferences`、`candidate_projects`。输入限制、422、幂等、持久快照与恢复语义以[现行目标契约](../../contracts/CURRENT_CONTRACTS.md)为准。每项都是用户提供的文本或待核验项目标识，不由网页提升为用户意图。
- 旧请求省略上下文时，系统从目标中提取明确要求；缺少关键条件时只给条件化替代方案或说明需补充的信息，不臆造用户的硬条件。用户提供候选为空时可搜索发现；提供候选时不得悄悄替换。
- 输出：目标与假设、候选、条件／事实矩阵、每项证据的 fact ID 和官方来源、冲突及未知项、条件化建议和改变建议的条件。矩阵行的判断限定为 `satisfied | not_satisfied | unknown | conflicting`；报告字段及人机核源分层以目标契约为准。机器准入与人工官方核源状态分别呈现。
- 任务六态、取消、事件补读、owner 隔离、调用和费用账本沿用现行契约；Agent 输出不得绕过事实准入。报告可以是 `partial` 或 `failed`，不得用完整排版掩盖关键证据缺失。

## 示例、边界和失败验收

1. PDF 例：接受“不能安装 Chromium”后以官方部署依据判断 Puppeteer 和 PDFKit，明确 HTML/CSS 复用与重新布局的取舍；改为允许 Chromium 后重新判断。不先写一个固定赢家；实际版式效果属于下一步验证。
2. ORM 例：同时 SQLite/PG 和后来只 PG 是不同 revision。官方声明支持某数据库不能证明 schema、驱动和迁移脚本可无成本互换；必须列证据与未知。
3. 语音例：asr/tts/dialogue 是本题角色。语言/方言、设备、地域和用量不明时保留未知；官方声明不能当老人音频准确率、自然度或端到端时延实测。
4. 边界：最低相关反证装不下不得静默删除；过期线索不能刷新读取时间绕过7天；revocation先提交阻断后续准入，admission先提交只保留其绑定在途请求，不能复用该准入再发另一个请求。
5. 异常：工具403/断连/超时应留下规划与失败反馈并有界处理；不能连续无证据重规划到完整成功。取消/超时释放资源但保留发生的调用及未知费用；报告排版齐全不算任务完成。
