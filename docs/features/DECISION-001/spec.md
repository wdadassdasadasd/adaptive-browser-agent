# DECISION-001：有证据的 Python 开源技术选型

状态：**已获批准的需求细化；代码按任务切片逐项验收，真实决策质量与正式放行仍未验证。** 用户于 2026-10-23 以“执行”授权本地规格／契约同步与相应离线业务开发。产品方向见 [ADR-0006](../../design/adr/0006-python-open-source-decision-agent.md)；现行任务、接口和正式放行仍以根目录 `SPEC.md`、`PLANS.md`、`docs/contracts/CURRENT_CONTRACTS.md` 及 `docs/evaluation/CURRENT_EVAL_PROTOCOL.json` 为准。本页细化 FR-013 和既有 FR-002／003／004／010，不改原 AC。

## 用户与目标

开发团队技术负责人需要在公开 Python 开源候选中选型。他描述用途、必须条件、偏好及已知候选；系统用官方可复查证据解释各候选满足什么、缺少什么、在何种条件下推荐什么。结论是决策辅助，不代替团队实测、许可证法律判断或代码兼容验证。

首版覆盖现行九题相关的浏览器工具、Python Web 框架和发布记录。仅研究公开非敏感材料，不访问登录后内容或执行外部写入。升级影响分析、跨语言候选、自动改依赖和 PR 属后续需求。

## 输入、输出与状态边界

- 输入：现有 `goal` 请求保持兼容；目标契约增加**可选** `decision_context`，包含 `use_case`、`must_have`、`preferences`、`candidate_projects`。输入限制、422、幂等、持久快照与恢复语义以[现行目标契约](../../contracts/CURRENT_CONTRACTS.md#decision-001-可选输入与兼容语义目标未实现)为准。每项都是用户提供的文本或待核验项目标识，不由网页提升为用户意图。
- 旧请求省略上下文时，系统从目标中提取明确要求；缺少关键条件时只给条件化替代方案或说明需补充的信息，不臆造用户的硬条件。用户提供候选为空时可搜索发现；提供候选时不得悄悄替换。
- 输出：目标与假设、候选、条件／事实矩阵、每项证据的 fact ID 和官方来源、冲突及未知项、条件化建议和改变建议的条件。矩阵行的判断限定为 `satisfied | not_satisfied | unknown | conflicting`；报告字段及人机核源分层以目标契约为准。机器准入与人工官方核源状态分别呈现。
- 任务六态、取消、事件补读、owner 隔离、调用和费用账本沿用现行契约；Agent 输出不得绕过事实准入。报告可以是 `partial` 或 `failed`，不得用完整排版掩盖关键证据缺失。

## 验收条件草案

| ID | 可观察行为 |
| --- | --- |
| DEC-AC-01 | 仅 `goal` 的既有请求与六路 API 保持兼容；输入的必须条件和偏好不被混为同一优先级。 |
| DEC-AC-02 | 每个关键比较结论指向已准入 fact ID、主体、官方 URL、最小片段与抓取时间；不匹配来源、主体或片段的材料不能支撑结论。 |
| DEC-AC-03 | 条件矩阵按候选 × 条件标示满足／不满足／未知及依据；无证据不写“满足”，来源冲突显式保留。 |
| DEC-AC-04 | 候选违反硬条件、关键事实缺失或决定性冲突时，不输出无条件赢家；偏好取舍写明条件和支持事实，不编造精确综合分。 |
| DEC-AC-05 | 改变同一场景的硬条件时，推荐或无法推荐的理由相应变化；仅改变页面中的诱导文字不得改变用户约束。 |
| DEC-AC-06 | 取消、超时、失租和预算停线时保留已提交事实、调用与费用，报告诚实说明未完成部分；未知用量／费用保持未知。 |
| DEC-AC-07 | [正式九题](../../evaluation/CURRENT_EVAL_PROTOCOL.json)的题面、尝试次数、分母和人工核源不变；补充决策复核独立记录且不冒充正式 full。 |

## 设计及验收风险

当前 [ReporterService](../../../backend/src/adaptive_research/agent/reporter.py)固定输出无法推荐，且 [P-02](../../audits/P02_PILOT_R11_FAILURE_TRIAGE_2026-10-23.md)尚无 full。先让官方事实可用并修复预算停止路径，再增加推荐能力。方案须在实施前审查目标契约、权限、提示注入和费用边界；真正的推荐有效性需要人工核源和技术负责人复核。离线 Mock 或模型评委只提供诊断证据。
