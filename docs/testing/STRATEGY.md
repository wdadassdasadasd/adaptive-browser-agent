# 按风险选择的测试与 Agent 评测策略

现行目标、AC 与门槛由根规格／契约和 [冻结协议](../evaluation/CURRENT_EVAL_PROTOCOL.json)决定；本页说明如何选择检查，不替换 [V1 测试矩阵](V1_TEST_MATRIX.md)或历史结果。

| 层 | 对象与典型证据 | 触发条件 |
| --- | --- | --- |
| L0 | Ruff、格式、类型、锁与配置校验；记录命令／退出码 | 改相应代码、依赖或配置时；文档变更至少检查链接与结构。 |
| L1 | 纯逻辑、状态、解析和失败边界单元测试 | 改业务决策、事实准入、预算或状态归约时。 |
| L2 | API／Schema／事件／数据库约束及兼容测试 | 改公开接口、持久结构或消息语义时。 |
| L3 | 真实隔离 PostgreSQL 上的 API、Worker、租约及事件集成 | 改事务、队列、取消、恢复或权限路径时。 |
| L4 | Vue → API → 任务及历史的端到端交互 | 改用户流程或跨端状态时。 |
| L5 | 崩溃、失租、数据库失联、未知结果及资源释放注入 | 改长任务／外部调用／恢复边界时。 |
| L6 | 官方来源、完整任务、轨迹、费用及人工核源的真实 Agent 评测 | 只有按现行协议和逐次授权执行；离线与 Mock 不计真实成功。 |

任务包先记录基线，再选足以覆盖改动风险的层；不机械要求文档修改运行全套 E2E。CI 现有 Python 3.12／3.13 离线检查、PostgreSQL 16 集成和前端检查见 [workflow](../../.github/workflows/ci.yml)；本地实际命令以当前环境和任务包记录为准。CI 绿灯不证明 Windows／WSL 冷启动或真实来源准确。

DECISION-001 的补充复核在**同一冻结报告快照**上逐项检查硬条件、事实支持、未知与冲突、条件变化后的理由；保存报告 SHA-256、fact ID、复核者和时间。它与正式九题分母独立，额外真实任务需要新预算及单独授权。发现断言或门槛失败时保留原样本并给出 No-Go，不通过删样本、降低阈值或将未知费用写零使其通过。
