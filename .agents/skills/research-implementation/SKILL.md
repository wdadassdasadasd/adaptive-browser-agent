# Authorized research implementation

Read `AGENTS.md`, `SPEC.md`, `PLANS.md`, [contracts](../../../docs/contracts/CURRENT_CONTRACTS.md), [sole protocol](../../../docs/evaluation/CURRENT_EVAL_PROTOCOL.json) and the existing task package. Supply methods within the applicable [project workflow](../../../docs/engineering/WORKFLOW.md); return evidence to the same record without restarting orchestration. Source/tests and dated evidence establish existing behaviour, not the unimplemented target.

1. Identify specific human authority, Task/Requirement/AC, owned files, current state, input/output and non-goals. The 40-path configuration approval is not business authority. The first proposed slice is DEC-M1-01, real authentication/raw drafts plus minimal supervisor; DEC-T07-01 is historical. Continue approved implementation and verified fixes without generic continuation prompts.
2. Plan affected boundaries. [ADR5](../../../docs/design/adr/0005-windows-worker-wsl-postgres.md) targets independent API/Worker and a new independent PostgreSQL cluster in WSL, Windows UI. Pg application tables own business truth; checkpoints hold bounded committed references. Ordinary startup validates identity/schema without DDL or setup. Exact environment/role/path/migration/dependency operations need their own authority; prove old-autostart isolation before starting WSL. Keep `browser-use/` upstream-owned.
3. Preserve accepted revisions, stable obligations, physical call identities, exact requests, cumulative deadlines and quotas. Unknown stops new project outbound; completed/unknown calls are not resent through replanning, recovery or new IDs. Final claim, cancellation/revocation and generation release follow contracts. Lost supervisor/Pg continuity isolates restored identities and disables research/memory; new CLI credentials only qualify limited draft/history access.
4. Implement the smallest authorized vertical result, preserving unrelated changes and historical source/data/fee/authorization evidence. Use meaningful risk-based tests from the [strategy](../../../docs/testing/STRATEGY.md). Core transaction/owner/lease behaviour needs real restricted isolated PostgreSQL and competing connections; skip or Mock is not that proof. Real model/Tokenizer/Browser requires separate authority. Direct API leads; Browser stays zero until connection-layer qualification; MCP practice is not an M1 requirement.
5. Inspect all task-owned committed/staged/unstaged/new-file content. Run focused checks, bind complete diff/content/results to fingerprints and obtain fresh-context independent review; security boundaries need scoped security review. Give raw requirements/AC and evidence, not intended findings. Validate defects, repair within scope, retest and independently re-review changed behaviour. Missing review remains pending.
6. Prepare runnable entry points, key diff, per-AC states, human steps/expected results, risks, rollback and skipped checks. Record actual human business acceptance and explanation/edit/regression evidence. Commit/push/PR need named task-scoped authority after a reviewable package; merge/release are separate.

Completion covers only the authorized result with actual evidence. Implementation, technical verification, review, human acceptance, value and release readiness are separate states.
